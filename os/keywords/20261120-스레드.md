# 스레드
- 프로세스 내부에서 실행되는 작은 작업 단위
- 하나의 프로세스 <-> 여러 스레드

## 특징
- 프로세스의 데이터 영역에 접근이 가능하다.
- 스레드끼리 서로의 데이터에 접근 가능하다.
- 스레드도 프로세스처럼 병렬 처리가 가능하다.
- 스레드는 thread stack이라는 메모리 공간만 갖는다.
- 일종의 함수로 구현된다.
- **하나의 스레드에 문제가 발생하면 다른 스레드에서도 문제가 발생 가능하니 주의해야 한다.**

## 장점
- 응답성(성능) 향상
    - 빠른 결과 제공
- 자원 공유 효율성 향상
- 동시성
    - 작업 병렬 처리
- 간결성
    - 작업을 분리해 코드 간결

## 단점
- 스레드 간 상호 간섭
- 성능 저하
    - 스레드 많이 생성 시 각각의 스레드들이 병렬로 실행되기 위해 컨텍스트 스위칭이 빈번하게 발생해 성능이 저하될 수 있음
- 동기화 문제
    - 공유 자원에 여러 스레드가 동시에 접근
    - 경쟁 상태 문제
- 자원 소비
    - 스레드마다 자원을 소비해 메모리 공간 부족 가능

## TCB
- Thread Control Block
    - 스레드 제어 블록
- PCB보다 적은 용량
    - 스레드 관련 데이터만 있으면 되기 때문
- 스레드가 생성될 때 마다 생성, 스레드가 삭제되면 종료

## 사용자 / 커널 스레드
### 사용자 스레드
- 운영체제 커널이 아닌 사용자 영역의 스레드 라이브러리에서 관리하는 스레드
- 스레드의 생성과 관리 빠름
- 커널의 개입 없이 스레드 전환
- 커널은 사용자 스레드의 존재를 알 수 없음
    - 하나의 실행 흐름으로 보임
- 하나의 스레드가 블로킹되면 다른 스레드도 영향을 받을 수 있음

### 커널 스레드
- 운영체제 커널이 직접 생성하고 관리하는 스레드
- 운영체제가 스레드의 실행과 스케줄링을 관리
- 여러 스레드가 서로 다른 CPU 코어에서 실행 가능
- 한 스레드가 블로킹되어도 다른 스레드 실행이 가능할 수 있음
- 커널의 개입 필요 -> 생성 / 전환 비용이 큼

### 매핑 방식
- 다대일(N:1)
    - 여러 사용자 스레드와 하나의 커널 스레드가 매핑
    - 운영체제 입장에서, 여러 사용자 스레드는 모르고 하나의 커널 스레드만 관리
    - 장점 : 사용자 스레드 간 전환을 사용자 영역에서 처리해 전환 비용 작음
    - 단점 : 하나의 커널 스레드가 블로킹되는 상황(사용자 스레드 하나가 블로킹)이 발생하면 다른 사용자 스레드들도 한번에 블로킹 될 수 있음
    - 단점 : 여러 CPU 코어에서 동시에 병렬 실행될 수 없음
- 일대일(1:1)
    - 사용자 스레드 하나와 커널 스레드 하나가 매핑
    - 장점 : 하나의 스레드가 블로킹 되어도 다른 스레드는 블로킹 되지 않음
    - 장점 : 여러 CPU 코어를 활용한 병렬 처리 가능
    - 단점 : 커널 스레드를 생성하고 관리하는 비용이 발생
- 다대다(M:N)
    - 여러 사용자 스레드와 여러 커널 스레드가 연결됨
    - 사용자 스레드 수 > 커널 스레드 수 상황이 가능
    - EX
        - 사용자 스레드 4개
        - 커널 스레드 2개
        - 커널 스레드 2개가 사용자 스레드 4개를 나누어서 실행
        - **사용자 스레드와 커널 스레드가 반드시 1:1로 고정되는 것이 아님**
    - 장점 : 모든 커널 스레드가 블로킹 되는 것이 아니면, 다른 사용자 스레드를 계속 실행 가능함
    - 장점 : 여러 CPU 코어를 활용한 병렬 처리 가능
    - 장점 : 커널 스레드 수를 조절하면서 여러 사용자 스레드 실행 가능
    - 단점 : M:N 관계의 연결, 스케줄링 구조가 복잡함

## 멀티스레딩과 멀티 프로세싱
### 멀티스레딩 (Multithreading)
- 하나의 프로세스 내부에서 여러 스레드가 동시에 작업 처리
- 특징
    - 메모리 공유 가능
    - 자원 절약 가능
    - 통신의 편리
    - 동기화 문제 발생 가능
- 동시성 문제를 해결하기 위해 Mutex, Semaphore, Lock 등을 사용한다.

### 멀티프로세싱 (Multiprocessing)
- 여러 개의 프로세스들이 각각 작업을 처리
- 특징
    - 메모리 독립적
    - 안정성
    - 병렬 처리 가능 ( 여러 CPU 코어 사용 )
    - 자원 사용량 많아짐
    - 프로세스 간 통신에 IPC를 사용해야 함
- IPC : Pipe, Shared Memory, Message Queue, Socket 등

### 동시성 VS 병렬성
- 동시성
    - 여러 작업을 번갈아 수행하면서 동시에 진행되는 것 처럼
- 병렬성
    - 여러 작업을 실제로 같은 시간에 수행
