# 프로세스
- 실행 중에 있는 프로그램
- 스케줄링의 대상인 작업(task)와 같은 의미
- 프로세스 내부에는 최소 1개의 스레드가 존재
    - 실제로는 스레드 단위로 스케쥴링

## 프로세스 영역
- Code : 프로그램을 실행시키는 실행 파일 내의 명령어들이 저장되는 공간
- Data : 전역 변수, static 변수의 할당
- Heap : 동적 할당을 위한 메모리 영역
- Stack : 지역변수, 함수 호출시 전달되는 인자들을 위한 영역

## 프로세스 스케줄링
- CPU는 하나인데 동시에 실행되어야 할 프로세스가 여러 개?
    - CPU가 고속으로 여러 프로세스를 일정한 기준으로 순서를 정해서 실행.
- 어떤 프로세스를 running 상태로 보낼까?
    - scheduling algorithm을 통해 기준을 정한다.
    - 대부분의 OS는 우선순위 알고리즘과 RR 알고리즘을 혼합하여 사용한다.

## 프로세스의 상태
- Created (생성)
    - 사용자가 요청한 작업이 커널에 등록됨
    - PCB가 생성되어 프로세스가 생성된 상태
    - **created -> ready** : 메모리 공간 검사 후 충분한 공간이 있으면 메모리 할당 후 준비 상태로
    - created -> suspended ready : 공간이 없으면 메모리 할당을 하지 않고 보류 준비로 변경
- Ready (준비)
    - CPU를 할당받기 위해 대기 중인 상태
    - 할당받으면 바로 실행할 준비가 된다
    - **ready -> running(디스패치)** : CPU를 받으면 실행 상태로 바뀜
    - ready -> suspended ready : 준비 상태에서 메모리를 뺏김...
- Running (실행)
    - CPU를 할당받아 실행 중인 상태
    - running -> ready(타임아웃) : CPU를 받아 실행하다가 시간 할당량을 소진해 뺏긴 상태
    - **running -> blocked** : 실행 상태의 프로세스가 입출력이 필요하게 되어 시스템 콜을 하고, 입출력 처리의 종료를 기다리는 상태 ( 이떄 CPU는 바로 준비 상태의 프로세스 하나를 선택해 실행한다. )
- Blocked (대기)
    - 프로세스가 실행되다가 바로 확보 불가능한 자원을 요청하면 CPU를 양도하고 요청한 일이 완료되기를 기다린다.
    - blocked -> ready : 입출력이 완료되어 CPU 재할당을 대기
    - blocked -> suspended blocked : 메모리의 여유 공간 확보를 위해 대기 상태에서 메모리를 뺏겨 보류 대기 상태로 바뀜
- Terminated (종료)
    - 프로세스가 종료될 때 아주 잠깐 거치는 상태
    - 모든 자원이 회수되고 PCB를 삭제한다.
- Suspended Ready (보류 준비)
    - 생성한 프로세스가 바로 메모리를 받지 못할 때, 준비 또는 실행 상태에서 메모리를 잃게 될 떄
    - 충분한 메모리 공간의 확보를 위해 준비 상태의 프로세스를 보류시키는 경우
    - running -> suspended ready : 높은 우선순위의 보류 대기 상태 프로세스가 준비 상태가 되어, 실행 상태의 프로세스로부터 CPU를 뺏는 경우
    - suspened blocked -> suspended ready : 보류 대기 상태에 있던 프로세스가 기다리던 입출력이 완료된 경우
    - suspended ready -> Ready : 다시 메모리를 받은 경우
- Suspended Blocked (보류 대기)
    - 대기 상태일 때 메모리 공간을 잃은 상태
    - blocked -> suspended blocked : 메모리 공간 확보를 위해 메모리를 잃은 상태
    - suspended blocked -> blocked : 메모리가 확보되어 대기가 된 경우
    - suspended blocked -> suspended ready : 입출력이나 기다리던 사건이 종료된 경우

## PCB
- 프로세스 제어 블록
- 운영체제가 각 프로세스를 관리하기 위해 사용하는 프로세스의 정보가 담긴 자료구조

### 저장되는 주요 정보
- PID : 프로세스 고유 식별 정보
- Process State : 프로세스 상태
- Program Counter : 다음 명령어 주소
- CPU Registers : CPU 레지스터 값
- CPU Scheduling Info : 우선순위, 스케줄링 관련 정보
- etc...

### 왜 필요한가
- 문맥 교환 때문
    - 프로세스를 교환할 때 PCB에 백업 -> 끝나고 다시 CPU에 PCB 값 불러오기
    - 운영체제가 여러 프로세스를 번갈아 실행하면서도, 각각의 실행 상태를 기억할 수 있도록 해주는 자료구조

## 프로세스의 생성과 종료
### 생성
- 프로세스는 여러 개의 자식 프로세스를 생성할 수 있다.
    - 부모와 자식이 병렬하게 실행을 계속
    - 부모는 자식이 실행을 종료할 때 까지 기다림
- 자식 프로세스는 두 가지 상태
    - 부모와 똑같은 프로그램
    - 부모와는 다른 새로운 프로그램
#### fork()
- 새로운 프로세스를 생성하는 시스템 콜
- 새로운 프로세스는 원래 프로세스의 주소 공간의 복사본으로 구성
    - 부모와 자식 프로세스가 쉽게 통신할 수 있도록 함
    - 자식 프로세스에서 `fork()` 의 반환값은 0
    - 부모 프로세스에서 `fork()` 의 반환값은 생성된 자식 프로세스의 PID
#### exec()
- 이진 파일을 메모리에 적재하고 그 프로그램을 실행하는 시스템 콜
- `fork()` 시스템 콜 이후에 둘 중 한 프로세스가 `exec()` 시스템 콜 사용
- `exec()` 를 사용한 프로세스는 자신의 메모리 공간을 새로운 프로세스로 교체

### 종료
- 프로세스가 종료된다면 운영체제는 사용하던 자원을 되찾아간다.
#### wait()
- 자식 프로세스가 종료될 때 까지 기다리는 시스템 콜
- 부모가 어느 자식이 종료되었는지 알 수 있도록 종료된 자식의 프로세스 식별자 반환

#### exit()
- 운영체제에게 자신의 삭제를 요청하고 종료하는 시스템 콜

#### 비자발적 종료
- 부모 프로세스의 시스템 콜 요청으로 종료
    - 자식의 PID를 알아야 함
- 오작동으로 인해 다른 사용자의 프로세스를 강제로 종료

#### 부모가 자식을 종료할 수 있는 경우
- 자식이 자신에게 할당된 자원을 초과해 사용
- 자식에게 할당된 작업이 더 없음 ( 필요 없어 짐 )
- 부모가 `exit()` 실행했을 때.
    - 만일 OS가 부모는 종료되었는데 자식이 실행되는걸 허용하지 않으면 종료

### 좀비 프로세스
- 종료되었지만 부모 프로세스가 `wait()` 를 아직 실행하지 않음
- 종료하게 되면 모든 프로세스들을 매우 짧은 시간동안 좀비 프로세스가 됨

### 고아 프로세스
- 부모 프로세스가 자식보다 먼저 종료될 경우 발생....
- UNIX에서는.. | 고아 프로세스의 새로운 부모 프로세스를 init 프로세스로 지정함으로써 문제 해결
    - init 프로세스는 주기적으로 `wait()` 호출해 고아 프로세스들의 종료 상태를 수집.
