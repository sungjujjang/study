# JWT
- Json Web Token으로, 웹 통신에서 서버측 데이터 저장 없이 인증을 수행하는 방식
- Stateless 구조이다
![jwt 구조](https://image.ahnlab.com/atip/content/image/20251216/0Od9ZccS6sXhJ5sYW6xSu1TpnUVgt708kiOpxlcx.png)
## Header
```
{
  "alg": "HS256",  // 서명 알고리즘
  "typ": "JWT"     // 토큰 타입
}
```
- Token의 메타 정보를 담고 있는 부분
- Base64로 인코딩되어 있음
## Payload
```
{
  "sub": "user123",           // 사용자 ID
  "name": "John Doe",         // 사용자 이름
  "role": "admin",            // 권한
  "iat": 1516239022,          // 발급 시각
  "exp": 1516242622           // 만료 시각
}
```
- 실제 전송하고자 하는 데이터 정보를 담고 있음
- 암호화가 아닌 **인코딩**이기 때문에 중요 정보를 담으면 안 된다.
## Signiture
```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  SECRET_KEY
)
```
- 키의 무결성을 검증하는 부분


## 문제점
### 로그아웃의 부재
- JWT는 서버가 저장하지 않으므로 로그아웃을 시킬 수 없다.
### 즉시 번경이 어려움
- 권한 번경 발생시 JWT를 수정해야 하는데, 수정이 불가함으로 새로 발급이 필요하다.
### 토큰 탈취 시 위험
- Authorization 토큰만 탈취하면 로그인이 가능함.

## Access Token과 Refresh Token
### 일반 JWT 토큰의 문제점
1. 유효기간을 길게 설정
```
토큰 탈취

↓

30일 동안 누구나 로그인 가능
```
2. 유효기간을 짧게 설정
```
15분마다 로그인해야 함
```
### Access Token
- API 호출 시 사용하는 토큰
```
POST /login

↓

Server

Access Token 발급
```
```
GET /users/me

Authorization:
Bearer AccessToken
```
- 유효기간이 짧음
	- 보통 10~30분
- 탈취돼도 오래 사용할 수 없음
### Refresh Token
```
Access Token 만료

↓

POST /auth/refresh

Refresh Token 전송

↓

새 Access Token 발급
```
- 유효기간이 김
	- 보통 7일~30일
- API 호출에는 사용하지 않음
- Access Token 재발급 전용
- **Refresh Token은 유효기간이 길기 때문에 보안이 매우 중요함**
- `HttpOnly + Secure Cookie` 저장
- 서버에서 Refresh Token을 관리, 로그아웃 시 토큰 삭제
