# N+1 문제
## 문제
- 기준 데이터를 조회하기 위한 쿼리 1번
- 기준 데이터를 따라 연관 데이터들을 각각 조회하기 위한 쿼리 N번 (연관 데이터 수 = N)  
**최종적으로 쿼리의 개수는 N+1번이 발생하게 됨**
- 쿼리 개수가 많아질수록 SQL에서 한번에 처리하는 방식보다 훨씬 늦어지게 됨
```java
for (Post p : posts) {
    p.getComments(); // 여기서 DB 추가 호출
}
```

## 해결방법
### Fetch Join
```sql
SELECT p FROM Post p JOIN FETCH p.comments
```
- 한 번에 SQL문으로 같이 가져옴

### Entity Graph (JPA 방식)
```java
@EntityGraph(attributePaths = "comments")
List<Post> findAll();
```
- Fetch Join 방식을 선언적으로 사용

### Batch Size
```java
@BatchSize(size = 100)
```
- N번 쿼리를 → IN 쿼리로 묶음
```sql
select * from comment where post_id in (1,2,3,...)
```
- 다른 방식에 비해 성능 떨어짐
