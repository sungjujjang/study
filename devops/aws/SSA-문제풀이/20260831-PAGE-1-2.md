# Problem

## 1. Application은 EC2 Instance, Database는 Amazon Aurora를 사용하는 이유는?

# Answer

Application → **EC2 Instance**
Database → **Amazon Aurora**

# Reason

* EC2 → **IAM** → **Secret Manager** → Username / Password → **Aurora**
* DB 인증 정보를 코드나 환경변수에 직접 저장하지 않고 **Secret Manager로 관리**
* Secret Manager를 통해 **보안성 향상 및 비밀번호 관리** 가능

---

# Problem

## 2. Aurora의 비밀번호를 Secret Manager에서 관리하고 Rotation을 적용할 때, SSM Parameter Store가 아닌 Secret Manager를 사용하는 이유는?

# Answer

**AWS Secrets Manager**

# Reason

1. **SSM Parameter Store**

   * SSM-Ps로 시크릿 정보는 저장 가능
   * 기본적으로 무료
   * 하지만 **RDS 비밀번호 Rotation을 기본 지원하지 않음**

2. **Secrets Manager**

   * RDS/Aurora와 연동하여 **자동 Rotation 지원**
   * DB 비밀번호를 주기적으로 변경하고 관리할 수 있음

---

# Problem

## 3. ALB 뒤에서 EC2로 구성하고, RDS의 쓰기 부하까지 처리하기 위해 사용하는 서비스는?

# Answer

**Aurora Auto Scaling**

# Reason

1. **RDS**

   * 자동으로 Read Replica 생성이 불가능한 경우가 있음

2. **Aurora의 Multi-AZ 기능**

   * 여러 AZ에 배치하여 **고가용성**을 확보할 수 있음

3. **Aurora Auto Scaling**

   * DB 부하에 따라 Read Replica를 자동으로 조절하여 읽기 부하를 분산할 수 있음

---

# Problem

## 4. S3와 RDS의 데이터를 대시보드 형태로 표시하려면?

# Answer

**Amazon QuickSight**

# Reason

* 대시보드 형태로 데이터를 **시각화**
* S3, RDS 등의 데이터를 가져와 분석 및 대시보드로 표현 가능
* 대시보드(시각화) → **QuickSight**

---

# Problem

## 5. 대용량 이미지를 압축하고 S3에 업로드한 후 처리하려면?

# Answer

**SQS + Lambda**

# Reason

* S3에 이미지 업로드
* S3 이벤트 발생
* **SQS Queue**에서 이벤트를 받아 처리
* **Lambda**에서 이미지 압축 등의 작업 수행
* 이미지 처리 요청이 많아지면 Queue에 쌓아서 순차적으로 처리 가능
* 이미지 처리에 부하가 생겨도 **SQS가 완충 역할**을 함

---

# Problem

## 6. 내 VPC에 타사 방화벽 서버를 설치하려면?

# Answer

**GWLB (Gateway Load Balancer)**

# Reason

* 일반적인 **L3 Load Balancer가 아님**
* 외부에서 들어오는 트래픽을 방화벽/보안 장비로 전달할 때 사용
* **GWLB → 방화벽 → VPC**
* 여러 VPC에 방화벽/보안 서비스를 중앙에서 제공할 수 있음
* 타사 방화벽 같은 **네트워크 가상 어플라이언스(VNF)**를 배치할 때 적합

# Problem

## 7. 전 세계 사이트에서 S3 버킷으로 파일을 업로드할 때, 전송 속도를 높이려면?

# Answer

**S3 Transfer Acceleration + Multipart Upload**

# Reason

1. **물리적 거리 문제**

   * 사용자가 S3 리전과 멀리 떨어져 있을 경우 업로드 속도가 느려질 수 있음
   * S3 Transfer Acceleration을 사용하면 **Site → Edge → S3** 형태로 전송

2. **대용량 데이터**

   * Multipart Upload를 사용하여 파일을 여러 파트로 나누어 병렬 업로드
   * 대용량 파일 업로드 성능 향상

3. **운영 복잡성 최적화**

   * 대용량 파일을 효율적으로 업로드 가능

---

# Problem

## 8. S3의 JSON 로그를 분석하고 기존 아키텍처의 변경을 최소화하면서 쿼리 기능을 제공하려면?

# Answer

**Amazon Athena**

# Reason

1. 로그 파일이 **S3에 저장되어 있음**

   * S3에 있는 데이터를 직접 분석할 수 있음
   * S3 분석 → **Athena**

2. 기존 아키텍처 변경을 최소화하면서 쿼리 가능

   * 별도의 데이터베이스로 데이터를 옮기지 않고 S3 데이터를 바로 SQL로 조회 가능

3. **쿼리한 데이터 양에 따라 비용 지불**

   * 사용한 데이터 양을 기준으로 비용이 발생

4. **운영 최적화**

   * 서버를 직접 관리할 필요 없이 서비스 형태로 사용 가능

# Problem

## 9. AWS Organizations에 속한 특정 유저만 S3에 접근하도록 제한하려면?

# Answer

**S3 Bucket Policy에서 PrincipalOrgID를 지정**

# Reason

* 특정 **AWS Organization에 속한 사용자/계정만 허용**
* `aws:PrincipalOrgID`를 사용하여 Organization ID를 기준으로 접근 제한
* 해당 Organization에 속하지 않은 주체의 S3 접근을 제한할 수 있음

---

# Problem

## 10. MSA 환경에서 수십 개의 서비스가 있고, 10만 명에게 메시지를 보내야 한다면 어떤 구조를 사용하는가?

# Answer

**SNS + SQS**

# Reason

* Producer → **SNS**
* SNS에서 여러 SQS Queue로 메시지를 전달

```text
              Producer
                  |
                 SNS
            /     |     \
        SQS-A   SQS-B   SQS-C
```

* 하나의 메시지를 여러 서비스에 전달해야 하는 **Pub/Sub 구조**
* 각 MSA 서비스가 자신의 SQS Queue를 가지고 메시지를 처리
* 서비스별로 독립적인 메시지 처리가 가능
* 대규모 트래픽에서도 메시지를 안정적으로 전달할 수 있음
