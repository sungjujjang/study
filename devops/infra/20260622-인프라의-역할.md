# 인프라 설계 시의 주의점
- 비 기능적 요건
	- 1년간 10분 이상 서비스를 정지시키지 않는다
- 기능적 요건
	- 비 기능적 요건을 구현하기 위해 필요한 기능
## 인프라의 신뢰성 - RAS
- R : 신뢰성
- A : 가용성
- S : 유지 보수성
### 검토하는 법
- 가동률 = MTBF / ( MTBF + MTTR )
- 장애 발생 간격 (MTBF) = 누적 사용 시간 / 고장 횟수
- 평균 복구 시간 (MTTR) = 누적 수리 시간 / 고장 횟수
  
**가동률을 축으로 각종 요소들을 결정함**
### 가동률을 높이기 위한 방법
- MTTR(평균 복구 시간)을 짧게 하거나, MTBF(장애 발생 간격)을 길게 한다
- 위를 해결하기 위해 다중화를 사용한다.
	- 다중화 : 구성 요소에서 장애가 발생한 경우에 다른 구성 요소가 그 처리를 넘겨받아 시스템 전체의 가용성을 높이도록 하는 것을 말함.
	- 다중화를 사용 시 MTTR이 짧아지거나 `0`이 되기도 한다
- 서버용 부품을 사용한다.
- 부품을 이중화한다.
	- 전원 장치의 이중화
	- 디스크의 RAID 구성
### 프로비저닝
**사용자 수 등을 예측하여 적절하게 리소스를 준히하는 것**
- 부하에 대응하는 방법
	- 스케일 업 : 서버 각 요소의 성능을 향상시키는 것
	- 스케일 아웃 : 서버 등 각 요소의 수를 늘리는 법
