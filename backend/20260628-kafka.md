# Kafka
대용량 데이터를 안전하게 처리하기 위한 Message Queue

## 구조
![그림 1](https://velog.velcdn.com/images%2Fcho876%2Fpost%2F91053846-a60f-4214-bee7-6fc6396570b2%2F%EC%8A%A4%ED%81%AC%EB%A6%B0%EC%83%B7%202022-03-12%20%EC%98%A4%ED%9B%84%2012.31.44.png)
- Producer
  - 메시지를 추가하는 역할
  - 데이터를 실질적으로 생성함
  - 예시: 유저가 요청하는 백엔드
- Kafka Cluster
  - 여러 Kafka Broker(Node)들이 모인 클러스터
  - Kafka는 확장성과 고가용성을 위해 Broker들이 Cluster로 구성된다.
- Consumer
  - 메시지를 소비하는 역할
  - Polling 방식을 사용해서 메시지를 Kafka에서 받아오게 된다.

### Broker 내부 구조
![그림 2](https://img1.daumcdn.net/thumb/R1280x0/?scode=mtistory2&fname=https%3A%2F%2Fblog.kakaocdn.net%2Fdna%2Fdi6Drq%2FbtrydfXoDwj%2FAAAAAAAAAAAAAAAAAAAAAOVZ-5Wb-y91qZrKKvWEvWS-QfbspoUzJOguwr_19rL7%2Fimg.png%3Fcredential%3DyqXZFxpELC7KVnFOS48ylbz2pIh7yKj8%26expires%3D1782831599%26allow_ip%3D%26allow_referer%3D%26signature%3DxNVwFSqtbCF8vk5%252BMNmieGU4hnY%253D)
**카프카에 저장되는 메시지는 topic으로 분류, topic은 여러개의 patition으로 나눠짐**
- Topic
  - 메시지를 구분하는 단위
- Patition
  - 메세지를 저장하는 물리적인 파일
  - 한개의 Topic은 한 개 이상의 Patition으로 구성된다.
  - Consumer은 Patiton 단위로 일한다
    - Partition 3개 == Consumer 3명
    -   ```
        Consumer A → Partition 0
        Consumer B → Partition 1
        Consumer C → Partition 2
        ```
- Consumer Group
  - 하나의 Topic을 읽는 기준
  - Consumer Group들은 Offset을 공유한다.
  - ```
                    Kafka Topic
                        ↓
            ┌───────────┼───────────┐
            ↓           ↓           ↓
          Group A     Group B    Group C
         (Payment)  (Analytics) (Notification)
    ```

## 왜 Kafka를 사용하는가?
### 느슨한 결합 (Decoupling)
**서비스끼리 직접 호출 안 함**
```
Order Service → Kafka 이벤트만 발행
Payment / Notification / Analytics는 독립
```
### 장애 격리 (Fault Isolation)
**하나에 서비스에 장애가 발생해도, 전체 서비스에는 영향이 없음**
```
Notification 장애 → 전체 시스템 영향 없음
```
### 트래픽 버퍼링 (Buffering)
**버퍼의 역할을 함**
```
Producer: 10,000 req/sec
Consumer: 2,000 req/sec
→ Kafka가 중간에서 저장
```

## 배포 방식
### Managed Kafka
- AWS MSK (Managed Streaming for Kafka)
- Confluent Cloud
```
Producer → AWS MSK (Kafka Cluster) → Consumer
```
- AWS가 브로커 관리
- 장애 복구 자동
- 스케일링 자동
- Zookeeper/KRaft 신경 X

### Kubernetes 위 Kafka (Strimzi)
```
Kubernetes
 ├─ kafka-0
 ├─ kafka-1
 ├─ kafka-2
```
- StatefulSet 사용
- PV 필요
- Operator (Strimzi) 사용

### EC2 직접 설치 (Bare metal / VM)
```
EC2-1 → Kafka broker
EC2-2 → Kafka broker
EC2-3 → Kafka broker
```
