# 엔티티 비교
- `equals()` 로 비교
    - JPA의 영속성 컨텍스트는 데이터베이스에서 가져온 엔티티가 이미 1차 캐시에 존재할 경우 해당 엔티티를 반환하게 된다.
    - 따라서 같은 영속성 컨텍스트라면 영속 상태인 엔티티의 동일성을 보장한다.
    - 이렇게 되면 `equals()`, `hashCode()` 등을 그대로 사용 가능하다.
    - but, 항상 같은 영속성 컨텍스트라는 보장은 없다.
- `hashCode`
    - Object가 가지는 고유한 정수 해시 값
- `@EqualsAndHashCode` 어노테이션 사용
    - 엔티티에 맞게 `equals()`, `hashCode()` 함수를 구현해준다.
    - 하지만 영속화 이전 엔티티(ID 필드가 아직 주입되지 않음)와 영속화된 엔티티는 동등함을 보장하지 못함.
    - 따라서 아래 방법을 통해 직접 구현해주는 편이 안전하다

- 구현 방법
    - 기본키를 통해 구현
    - PK를 제외하고 모든 필드를 비교해 구현
    - 비지니스 키를 통해 구현 (번경 불가능하진 않지만, 번경의 횟수가 적고 데이터베이스 제약 조건을 통해 유일성이 보장되는 비지니스 키)

## 구현 예시
```java
@Override
public final boolean equals(Object o) {
    if (this == o) {
        return true;
    }
    if (!(o instanceof Account account)) {
        return false;
    }

    return getId() != null && Objects.equals(getId(), account.getId());
}

@Override
public final int hashCode() {
    return Objects.hash(getId);
}
```
